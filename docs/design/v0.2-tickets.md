## v0.2-1. 역할 표시 단순화 — "방장/멤버" 배지 제거, 왕관은 소유자에게만 (Din, 2026-09-15)

**배경(가인님 지시)**: 지금 멤버 목록의 모든 사람에게 `RoleBadge`("방장"
또는 "멤버" 텍스트 배지)가 붙는다. 멤버에게도 "멤버"라는 배지가 붙는 건
불필요한 위계감을 준다 — 애초에 이번 라운드에서 **초대 권한을 모든 멤버에게
열어서**(`create_relationship_invitation` RPC는 원래도 멤버 여부만 체크하고
owner로 제한하지 않았다 — `group_detail_screen.dart`의 "화면 요구사항에
따라 owner로 한정" 주석이 그 제약의 출처), 이제 owner와 member의 실질적
권한 차이는 **"멤버 내보내기" 단 하나**만 남는다. 배지 두 종류를 유지할
이유가 없다.

**확정**: 그룹을 만든 사람(owner) 이름 옆에 작은 왕관류 아이콘 하나만 붙이고,
나머지 멤버에게는 **아무 배지도 안 붙인다.**

### 핵심 원칙 — "권한 표시"가 아니라 "만든 사람 표시"로 읽혀야 한다

지금 실제로 남는 owner 전용 기능은 "멤버 내보내기" 하나뿐이라, 아이콘이
"이 사람이 권한이 더 많다"로 읽히면 실제 권한 차이(내보내기 버튼 하나)보다
과장된 인상을 준다. 그래서:

- 아이콘은 **작고 조용하게** — 색은 M3가 파생한 중립 톤(`onSurfaceVariant`,
  인디고 시드에서 은은하게 틴트됨)을 쓴다. **채도 높은 `colorScheme.primary`
  (인디고) 자체를 쓰지 않는다** — 진한 브랜드 색을 쓰면 오히려 "강조·특권"
  으로 읽혀 목적과 반대로 간다.
- 로즈(`#D4685E`/하트 계열)도 쓰지 않는다 — 로고 2B의 색 역할 분리 논리상
  로즈는 "애정·특별함"에 예약된 색이다("애정은 하트 하나에만 몰아준다").
  방장 표시에 로즈를 쓰면 "이 사람이 더 특별하다/사랑받는다"는 의도치 않은
  뜻이 섞인다. 방장 여부는 감정이 아니라 사실(fact) 정보이므로 중립 톤이
  맞다.
- 크기도 본문 텍스트와 비슷하게(16dp) — 옆에 서 있는 닉네임보다 시각적
  무게가 커지지 않게 한다. 배경 칩(`Container`+`BoxDecoration`)도 없앤다 —
  칩 모양 자체가 "상태 라벨"처럼 보여 위계감을 만든다. 아이콘 단독이 훨씬
  가볍다.
- 접근성 라벨과 툴팁 문구를 **"방장"/"관리자" 같은 권한 냄새 나는 단어가
  아니라 "이 그룹을 만든 사람"**으로 정한다 — 시각 아이콘만으로는 의미가
  모호할 수 있어 문구가 그 오독을 막는 마지막 방어선이다.

### 아이콘 선택 — Material 아이콘으로 충분한가

**충분하다.** 이 컴포넌트는 아주 작고 저빈도(멤버 목록 한정)라 SVG 애셋을
새로 추가하고 `flutter_svg` 같은 의존성을 얹을 정도의 무게가 아니다.
Material 아이콘 폰트 안에서 고른다.

- **1순위: `Icons.workspace_premium`** — 리본 달린 메달 모양. "표준적인
  왕관"은 아니지만 "이 사람이 뭔가를 만들었다/시작했다"는 인상을 주는
  아이콘 중 Flutter 기본 아이콘셋에서 가장 근접하다.
- **Diana 확인 필요**: 이 아이콘이 실제로 현재 Flutter SDK의 `Icons`
  클래스에 있는지 IDE 자동완성으로 먼저 확인해달라(Din은 로컬에 Flutter
  툴체인이 없어 직접 컴파일 검증을 못 했다). 없거나 렌더가 어색하면 아래
  순서로 대체:
  1. `Icons.military_tech` (훈장 모양, 비슷한 톤)
  2. `Icons.star_rounded` (별 — 다만 "즐겨찾기/평점"으로 오독될 여지가
     제일 크므로 최후순위)
- 진짜 왕관 글리프(👑에 가까운 것)는 고전 Material Icons 세트에 없다.
  Material Symbols(신규 가변 아이콘 폰트)에는 있을 수 있으나, 그걸 쓰려면
  별도 폰트/패키지 배선이 필요해 이번 범위에서는 배제한다 — "왕관"이라는
  글자 그대로의 모양보다 "이 사람이 만든 그룹"이라는 의미 전달이 더
  중요하고, 위 대체 아이콘들로 그 의미는 충분히 전달된다.

### 스펙 표

| 항목 | 값 |
|---|---|
| 아이콘 | `Icons.workspace_premium`(확인 안 되면 `Icons.military_tech` → `Icons.star_rounded` 순으로 대체) |
| 크기 | `16` (본문 텍스트 라인하이트와 비슷하게, 닉네임보다 커지지 않게) |
| 색 | `Theme.of(context).colorScheme.onSurfaceVariant` (인디고 시드에서 자동 파생되는 중립 톤 — `primary`/`tertiary` 등 채도 높은 색 금지) |
| 배경/칩 | 없음. 아이콘 단독, 배경 컨테이너·둥근 모서리 없음 |
| 위치 | 닉네임 텍스트 오른쪽, `Row`로 나란히. 간격 `SizedBox(width: 4)` |
| 일반 멤버 | 아무것도 안 붙임(아이콘도, 배지도, 여백조차 남기지 않음 — 조건부 렌더) |
| 툴팁(마우스/롱프레스) | `Tooltip(message: '이 그룹을 만든 사람')` |
| 스크린리더 대체텍스트 | `Icon(..., semanticLabel: '이 그룹을 만든 사람')` — "왕관"/"아이콘"/"방장" 같은 단어를 쓰지 않는다. TalkBack/VoiceOver가 "이 그룹을 만든 사람"만 읽으면 된다 |

### 구현 메모 (Diana)

- `app/lib/features/relationships/presentation/widgets/role_badge.dart`의
  `RoleBadge` 위젯은 "owner/member 배지"라는 개념 자체가 사라지므로, 그대로
  고치기보다 **이름을 바꿔 새로 만드는 걸 권장**한다(예: `owner_mark.dart`의
  `OwnerMark` — `isOwner`가 false면 `SizedBox.shrink()` 반환). 옛 이름을
  남겨두면 나중에 읽는 사람이 "아직도 role 배지 두 종류가 있나?" 헷갈린다.
- `group_detail_screen.dart:322`의 `subtitle: RoleBadge(isOwner: member.isOwner)`
  줄을 통째로 없앤다(subtitle 자체를 지운다 — `null`). 대신 `title`을
  `Row(children: [Text(member.nickname), if (member.isOwner) ...])`로 바꿔
  아이콘을 이름 옆에 인라인으로 붙인다.
- **같은 커밋에 "초대 코드 만들기" 버튼의 `if (isOwner)` 가드도 제거**한다
  (`group_detail_screen.dart` 약 339행). 이걸 빼먹으면 "권한 차이는 내보내기
  하나만 남았다"는 전제와 화면이 어긋난다 — 배지 제거와 버튼 노출 확대는
  같은 결정의 앞뒤라 한 커밋으로 묶는 게 맞다. `initState`/build 상단의
  `isOwner` 관련 주석도 "member도 화면에서 초대 가능"으로 갱신.
- 회귀 테스트(Tom): 멤버 목록에서 owner 1명에게만 아이콘이 뜨는지, 일반
  멤버에게는 아무 위젯도 없는지, "초대 코드 만들기" 버튼이 member 계정으로
  로그인해도 보이는지 세 가지를 확인 케이스에 추가.
